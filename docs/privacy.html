Privacy policy

Effective and last updated: October 15, 2026

Yahoo Fantasy Sync is a personal, non-commercial application for reading Yahoo Fantasy Football data and synchronizing it into Google Sheets controlled by the person running the application.

At a glance

The app runs on your computer. It reads Yahoo data and writes Google Sheets with your authorization. OAuth credentials and tokens are saved locally. The project has no developer-operated data collection server.

1. Google permissions and account access

The application uses the Google OAuth authorization code flow for an installed Desktop application. You sign in directly with Google in your browser. The app does not receive your Google password.

The Google OAuth scope requested by the current implementation is:

https://www.googleapis.com/auth/spreadsheets

This scope grants permission to see, edit, create, and delete all Google Sheets spreadsheets accessible through the authorized account. It is broader than access to only the app’s output files. The current implementation uses it to create dedicated output spreadsheets and to read and update configured spreadsheet IDs; it does not include a spreadsheet-file deletion operation.

The app requests this scope to support both newly created spreadsheets and existing spreadsheets whose IDs you explicitly configure. It does not request Gmail, contacts, calendar, general Google Drive access, or separate email/profile scopes. Enabling the Drive API in a Cloud project does not itself grant the application Drive-wide access.

A refresh token enables later local commands to obtain access tokens without asking you to sign in each time, while the grant remains valid. Google may expire or revoke access, and you can revoke it yourself.

2. Data accessed and how it is used

The app reads the structure and relevant existing values of its configured output spreadsheets, including spreadsheet and tab identifiers, tab properties, Dashboard values, and History identifiers. These checks help keep leagues separate, preserve valid data, and prevent duplicate snapshots. An explicitly configured existing spreadsheet must be one you are authorized to edit.

It creates and updates tabs for the dashboard, rosters, standings, free agents, waivers, matchups, scoring settings, transactions, and snapshot history. It uses spreadsheet metadata to associate each output file with its league. Current-state tabs are replaced only after the corresponding Yahoo data has been retrieved and validated. Historical data is appended when new or changed.

Yahoo data can include league settings, team and player identifiers, roster positions, injury designations, scores, transactions, and other fields returned by Yahoo, including manager information when provided. These records may be included in output spreadsheets and local JSON snapshots. Yahoo access is read-only: no lineup changes, trades, or waiver claims are submitted.

3. Where data and credentials are stored

  • On your computer: the Desktop OAuth client JSON is stored locally, by default in .credentials/google-client.json. Access and refresh tokens are stored by default in .state/google-token.json. Tokens include expiry information and a client-identity fingerprint.
  • Local sync records: spreadsheet IDs, URLs, sync reports, and configuration are saved in local state or environment files. Yahoo JSON snapshots are saved in the local snapshots/ directory by default. These paths can be changed by the person running the app.
  • In your Google account: synchronized fantasy data and its history are stored in the output Google Sheets. Existing file permissions and any account or organization sharing policies apply. The app does not change sharing permissions or publish spreadsheet contents.

The default credential, environment, token, state, and snapshot paths are excluded from Git. Application-written token and state files use owner-only file permissions on supported local systems. The app does not itself encrypt these local JSON files; their protection also depends on your computer account, disk security, and backups. Protect any custom storage paths too.

API requests and token exchanges use HTTPS with the official Yahoo and Google services. Authorization codes are processed by the local application; the Google callback listens temporarily on the computer’s loopback address. The app does not intentionally print tokens or client secrets in its logs. Sync logs can include league names, counts, errors, and spreadsheet URLs.

4. Sharing, secondary use, and Google data policy

Google API data is used to provide the spreadsheet synchronization and integrity checks described here. It is not sold, used for advertising, or used by this application to train AI models. The project does not operate a remote database or analytics service that receives your spreadsheet contents or OAuth tokens.

The app sends Yahoo data from your computer to Google Sheets as its primary function. Yahoo and Google process requests under their own applicable terms and privacy policies. The app does not automatically send spreadsheet data to ChatGPT or another AI service. If you separately connect your spreadsheets to another service, or share them with another person, that is a separate authorization and is governed by that service’s policies and your sharing choices.

Yahoo Fantasy Sync’s use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements. Google data is used only for the disclosed user-facing functionality.

5. Retention and deleting saved data

Local configuration, tokens, sync records, and JSON snapshots remain on your computer until you remove them. The app does not automatically delete old snapshots. Output spreadsheets and their History tabs remain in your Google account until you edit or delete them; the app does not set an automatic retention period.

To remove saved data, stop any running sync, delete the local credential, token, state, and snapshot files you no longer want, and delete the output spreadsheets from Google Drive. Remove any copies in your own backups as needed. Google controls retention for its services and Trash. Deleting local tokens does not by itself revoke the OAuth grant, and revoking the grant does not erase data that was already saved.

6. Revoking access

  1. Open Google Account → Third-party connections.
  2. Select the app name shown on your OAuth consent screen, then remove its access or connection using Google’s available controls.
  3. Remove the saved local Google token file if you no longer want the application to reuse it. Future Google API calls will require a valid authorization.

Yahoo authorization can be managed separately in your Yahoo account security settings. Removing Google access does not remove Yahoo access, or vice versa.

7. This public website

This GitHub Pages website provides project information and this policy. It does not run synchronization, accept uploaded credentials, contain private league data, or provide a sign-in form. It includes no application analytics, advertising scripts, cookies set by our code, or third-party embedded content.

GitHub hosts the website and logs visitors’ IP addresses for security purposes. See GitHub Pages data collection and the GitHub Privacy Statement. Following an external link takes you to a service with its own privacy practices.

8. Questions and policy updates

The application is maintained by the owner of the Yahoo Fantasy Sync repository. For a private privacy request, use the support contact displayed on the application’s Google OAuth consent screen. General project questions can be raised through GitHub Issues; do not post credentials, tokens, account details, or private league data there.

Changes to data handling will be reflected on this page with a revised date. If a change requires additional Google permissions or changes the disclosed use of Google data, users will be informed and asked for the required consent before that access or use begins.
